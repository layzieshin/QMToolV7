# License Specification (P0)

Status: Canonical (P0)  
Valid from: 2026-06-12  
Canonical index: `docs/DOCS_CANONICAL_INDEX.md`

## Scope

Offline-capable module licensing for QM-Tool. The **customer application** imports and validates licenses only. License **issuing** is an internal operator tool (`tools/internal_license_issuer/`) and must never ship in customer bundles.

## Base license vs. module lock

The license file is the **base license**: it carries customer metadata, machine binding, signature, and `enabled_modules`. It is **not** an application start blocker. The app always starts; only modules with a `license_tag` (currently `training`) are locked when the base license is missing, invalid, expired, or does not enable the module.

## Schema v1

```json
{
  "schema_version": 1,
  "license_id": "LIC-…",
  "license_type": "trial",
  "issued_to": "Customer name",
  "customer_id": "CUST-…",
  "issued_at": "2026-06-12T10:00:00+00:00",
  "expires_at": "2027-06-12T23:59:59+00:00",
  "enabled_modules": ["training"],
  "machine_id": "qmt-…",
  "key_id": "prod-key",
  "signature": "<base64 Ed25519>"
}
```

- `license_type`: `trial` (requires `expires_at`, hard expiry) or `full` (`expires_at: null`, no expiry)
- `enabled_modules`: module tags from `core_license_tags()` (currently `training`)

## Machine ID

- Generated by `qm_platform/licensing/machine_id.py`
- Windows: prefers `MachineGuid` from registry (stable across hostname changes)
- Fallback: SHA256 of MAC node id only (`fallback_mac_address`)
- Format: `qmt-` + 16 hex chars
- GUI shows: *„Diese Maschinen-ID wird zur Ausstellung der Lizenz benötigt.“*

## License code

Transport encoding of the signed JSON:

```text
QMT1.<base64url(compact_json)>
```

Import decodes to the same payload as `license.json`.

## Customer application

- Public keys: `qm_platform/licensing/keys/prod_ed25519_public.pem` (and dev key in dev mode only)
- Ports: `license_service`, `license_guard`
- Enforcement: lifecycle `ensure_license`, `LicensedPortProxy` on licensed module APIs, GUI nav decoration
- CLI: `license-check`, `doctor` (license:* checks)

## Internal issuer (not shipped)

```bash
python tools/internal_license_issuer/create_license.py create-license \
  --type trial|full \
  --customer-id … \
  --issued-to … \
  --machine-id … \
  --enable-module training \
  --expires-at … \
  --private-key-pem /EXTERN/prod_ed25519_private.pem \
  --out license.json \
  --out-code license.txt
```

Private keys: never in git, never in customer bundles. Use `QMT_LICENSE_ISSUER_KEY` or `--private-key-pem` pointing outside the repo.

## Build gate

`packaging/verify_customer_bundle.py` must pass after `packaging/build_onedir.py`. Build **fails** if private keys, `tools/internal_license_issuer/`, or legacy generator scripts appear in the bundle.

## Agent rule

The issuer is internal only. The app must never generate production licenses in GUI, CLI, or bootstrap.
